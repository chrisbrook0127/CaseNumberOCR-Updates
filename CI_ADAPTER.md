# MFCase Windows CI adapter
This repo's main contains historical app/test tooling; current release source is on verified release commits, not main. The non-publishing workflow checks the proposed main-based checkout's existing unit suite and both pinned release sources independently. Passing checks on pinned releases never certifies a new application change. When developing a new release, adapt its actual source/build/test path and immutable commit before certifying or publishing that release.

Canonical script: scripts/ci.ps1 -Phase Setup|Test|Package|VerifyPackage -Target Legacy|Stable|Candidate -Root <checkout>. Python 3.11 on Windows. Dependencies reuse existing workflow requirements (numpy, pillow, pymupdf<2.0, opencv-python-headless for release tests); no verified lockfile is present, so this setup does not claim fully reproducible dependency resolution. Real unit discovery fails on zero tests or failing tests. Legacy target only validates the historical checkout's real regression suite and compilation, not release packaging. Stable uses tools/verify_v603.py prepare/updater to stage and check published exact installer/updater, run inherited tests and exercise actual updater replacement on synthetic data. Candidate uses tools/build_v604_test.py assemble/package, hash-verified stable release input, real tests and synthetic updater-preservation checks. VerifyPackage independently checks ZIP safety, version, expected asset names, hashes and exact program source identity. The candidate builder generates its own digest manifest; candidate ZIPs are local runner artifacts only. Neither script nor workflow can publish releases or upload artifacts. Existing publish workflows unchanged; use separate authorized release gates.

CI uses read-only permissions, reviewed existing checkout/setup-python actions, no private fixtures, no release token writes, no untrusted pull_request_target, and no package export. No real workstation installation, OCR accuracy/throughput, or user-data verification implied by hosted CI. Required acceptance: actual Windows runs, counts, nonzero failure behavior, archive and updater checks. Check actual run and note any missing source/dependency/runner blockers rather than passing a placeholder.
