# MFCase development instructions
Scope: standalone MFCase and its update infrastructure. Do not apply its domain rules to the separate MFCase-Complete subtree; follow that project's own approved instructions.

Before authorized development, load the latest available Software Development Standards plugin, repository PROJECT_RULES.md, APP_BASELINE.md, PROJECT_STATE.md, WORK_LOG.md, CHANGELOG.md, and relevant source. Reconcile actual repository, branch, commit, released and installed versions and source archive hashes. This public repository is both an update feed and a historical source/build archive; main is not necessarily the current production source. Do not infer that a newer number is approved. Keep work on an isolated branch/worktree; preserve existing dirty work and coordinate one writer per task.

AUDIT and STATUS are read-only. FIX, TEST, OPTIMIZE, LOCK, BUILD, PUBLISH, ROLLBACK, SYNC and CONTINUE follow the current plugin command reference, explicit scope and release gates. Never replace recognition/learning/UI/file behavior or stable releases incidentally. Do not treat a suggestion as manual approval. Respect local learning and offline operation; no private samples, models, user data, unredacted logs, credentials, local paths, or private task details in this public repository or CI. Use authorized private storage for detailed task checkpoints. Preserve original files and rollback.

Use existing verified tests, build/verification scripts and release workflows on the exact applicable source revision. Read CI_ADAPTER.md before running CI. Run real tests, fail closed, record evidence separately for Windows GUI, recognition accuracy, performance, packaging, updater and Sources. Do not publish or promote a release merely because CI passes. For any authorized implementation, update the sanitized state and work log after milestones; record private details only in authorized private storage. Reconcile uncertain writes before retrying. Never claim unattended continuation or a Sources upload without evidence.
